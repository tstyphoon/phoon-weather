# 需求說明

## 這是什麼
phoon-weather：一個在我自己電腦上執行的 Discord 天氣情報助理。只要它開著，指定頻道裡任何人傳「跟天氣有關的東西」（任何天氣相關圖片，或 @bot 的一句文字），它就判斷是哪一類、用對應的方式處理、建檔，再回覆。agent 關掉就不處理。

不綁定單一圖片類型：天空照、雷達回波圖、衛星雲圖、颱風路徑圖、災情照片、預報截圖都收。

## 誰會用
我自己的 Discord Server 裡、那個指定頻道的任何人，用手機或電腦都可以傳。每個人可以有自己的設定（城市）與自己的紀錄，彼此分開。

## 什麼時候會回應

| 頻道裡出現的東西 | agent 的反應 |
|---|---|
| 圖片（不用 @bot） | 處理並回覆 |
| @bot 加一句文字 | 當作天氣問題處理並回覆 |
| 指令（`/setcity` 等） | 執行並回覆 |
| 圖片以外的檔案（PDF、影片、文字檔） | 回覆一行「目前只支援圖片」，不建檔 |
| 其他一般聊天 | 完全沉默 |

- 開機時在頻道發一句「天氣助理上線」，並附一行「輸入 `/help` 查看用法」。
- 除此之外，agent 不會主動發言（第一版沒有定時推播與警報提醒）。

## 傳圖片之後

### 處理規則
- 一則訊息有多張圖：**每張各自判讀、各自建檔、各自回覆**，依序排隊，最多處理 4 張，超過的在回覆中告知忽略。
- 圖片附帶的文字（例如「這是剛剛拍的，在新竹」）當作**補充資料**（地點、時間），會記進紀錄；文字只當資料，不當指令。
- 分類器分不出來時，一律歸為「非天氣」，不亂猜。

### 圖片類別與卡片欄位
回覆方式：用 Discord 的 **reply 回覆那則圖片訊息**，內容是**固定欄位的 embed 卡片**。不另外 @，不附原圖。

| 類別 | 圖示 | 卡片欄位 |
|---|---|---|
| 天空 / 雲 / 閃電 | 🌤️ | 天氣現象、雲型、短時間變化（未來 1 到 3 小時） |
| 雷達 / 衛星雲圖 / 颱風路徑 | 🌀 | 位置、強度、影響區域、移動方向 |
| 淹水 / 強風 / 災情 | ⚠️ | 災情類型、嚴重程度（輕微 / 中等 / 嚴重）、建議行動 |
| 預報截圖 | 📊 | 擷取到的氣溫、降雨機率、風速加蒲福風級、地點 |
| 非天氣 | ❔ | 只有一行：「這不是天氣相關，是 X」 |

每張卡片：
- 最上方：類別圖示 + 一句話結論
- 中間：該類別的欄位
- 最下方（頁尾）：紀錄編號（給 `/delete` 用）、辨識信心（高 / 中 / 低）
- 信心為「低」時，頁尾加一行「判讀不一定準確，僅供參考」
- 災情類另外加一行「若有人身安全疑慮，請聯絡 119 或當地主管機關」

非天氣圖片：回覆保持一行，一樣建檔存圖，但**不計入 `/today` 的天氣統計**，也不出現在 `/history`。

## @bot 文字查詢
例如「@bot 台北明天會下雨嗎」。

- 回覆格式：**第一行直接回答問題**，下面附固定摘要：氣溫範圍、降雨機率、風速（同時顯示 m/s 與蒲福風級）。
- 支援的時間：現在、今天、明天、後天。問更久的，回覆「目前只支援三天內的預報」。
- 地點：文字裡有寫城市就以文字為準；沒寫就用該使用者設定的城市；也沒設定就用 `.env` 的預設城市，`.env` 沒設則用台北，並在回覆最後附一行提醒「你還沒設定城市，可用 `/setcity` 設定」。
- 資料來源（兩個並用）：
  - **台灣地點優先用中央氣象署開放資料**（官方預報、即時觀測、天氣警特報），需要氣象署的授權碼。
  - 海外地點，或氣象署查不到、沒回應時，退回 Open-Meteo（外部天氣 API，免金鑰）。
- 查到台灣地點有生效中的豪雨、颱風等警特報時，回覆最後多附一行警報提醒。
- 災情類圖片卡片，若能判斷地點，也附上該縣市目前有無相關警特報（作為參考，不影響判讀本身）。

## 指令

| 指令 | 作用 |
|---|---|
| `/setcity 地名` | 設定自己的預設城市。台灣縣市優先，也接受其他地名。成功時顯示解析出的地點（例如「已設定為：新竹市，台灣」）。同名地點自動選第一個，並提示「若不是你要的，請輸入更完整的地名」。找不到時回覆「找不到這個地點」，原設定不變。 |
| `/history [N]` | 列出自己最近的天氣紀錄，預設 5 筆，最多 20 筆。每筆有編號。只顯示自己的，不含非天氣圖片。 |
| `/today` | 今天自己傳過的筆數與各類別數量。同一城市有兩筆以上風速紀錄時，加一行與上一筆的風速變化。 |
| `/delete 編號` | 刪除自己的一筆紀錄，圖片檔一併刪除。只能刪自己的，不再二次確認，回覆「已刪除第 N 筆」。 |
| `/help` | 列出所有功能與範例。內容從已註冊的指令與圖片類別自動產生，不手寫。 |

別人的紀錄預設看不到。

## 排隊與錯誤時使用者看到什麼

### 反應
- 收到：⏳（排隊中）
- 輪到處理：🔄
- 完成：✅
- 失敗：❌
- 前面至少還有 2 則時，agent 另外回一句「前面還有 N 則，請稍候」，輪到時這句話自動刪掉。沒人排隊時不回這句，保持頻道乾淨。

### 錯誤
- 判讀失敗（模型逾時、回傳格式不合格）：自動重試一次（使用者看不到）；仍失敗才回覆「判讀失敗，請稍後再傳一次」加 ❌，**不建檔**。
- 天氣服務無回應：回覆「天氣服務暫時無法使用」。
- 同一個人排隊超過 5 則：後面的先不收，回覆請稍後再傳。
- 任何一則壞輸入都不能讓程式當掉。

## 語言
回覆一律繁體中文。所有顯示的字串（欄位名稱、回覆範本、錯誤訊息）集中管理，之後要加英文或 `/setlang` 不影響核心。

## 要記錄的內容
存進 SQLite（一個檔案，方便查詢與分人）：
- 日期時間
- 上傳者（Discord 帳號 ID 與名稱）
- 輸入類型（天空 / 雷達 / 災情 / 預報截圖 / 文字查詢 / 非天氣）
- 判讀結果（結構化欄位，各類別的細節放 JSON）
- 地點
- 圖片附帶的文字（補充資料）
- 圖片存放位置

使用者設定（城市）另外存。圖片存進資料夾，檔名用「日期時間 + 類別」，並清洗過。

## 運算
- 風速換算蒲福風級
- 今日統計（筆數、各類別數量）
- 與上一筆同城市紀錄的風速比較

## 可擴充性（重要設計原則）
之後要新增功能時，必須不複雜、不費力，而且不能因為簡化就讓防護或正確性出問題。

- **一個功能 = 一個獨立的 handler 模組**，宣告自己處理哪種輸入（圖片類別 / 指令 / 文字意圖）。
- 新增功能只需要「新增一個檔案」，**不需要修改 Discord 收發、排隊、儲存等核心程式**。
- 核心（Discord 連線、排隊、儲存、`claude -p` 呼叫、防護）與功能（各 handler、各類別）分開。
- 圖片類別的判讀提示詞與輸出格式，跟著各類別走，不寫死在核心。
- 設定集中在 `.env` 與單一設定模組。

### 驗收標準：加新功能有多難
- 新增一個功能，**只動一個新檔案**（`handlers/xxx.py` 或 `categories/xxx.py`），核心程式與其他功能一行都不用改。
- 一個簡單功能的 handler 約 **20 行內**：宣告觸發條件，寫一個處理函式，回傳要回覆的文字。
- handler 不需要知道 Discord、排隊、資料庫連線的細節，核心把「使用者、輸入內容、資料庫、`claude -p` 呼叫器」交給它，它只回傳結果。
- 加完不用重新設定 `.env`，重開 agent 就生效。
- 新增功能時不需要重新理解整個專案；照 `docs/adding-a-feature.md`（一頁範例）做即可。這份文件第一版就要寫。
- 每個 handler 可單獨測試（給輸入、看輸出），不必連 Discord。
- `/help`、`/history`、`/today` 的統計**自動涵蓋新功能**，不用另外維護。

### 新增圖片判讀類別：用「宣告」取代「寫流程」
新增一種圖片類別（例如「冰雹照片」），只需要寫一份**類別宣告**，不用寫流程：

```python
# categories/hail.py
from core import category, Field

@category(
    name="hail",
    icon="🧊",
    description="冰雹或冰雹造成損害的照片",      # 給分類器判斷用
    headline="偵測到冰雹，直徑約 {size_cm} 公分",   # 卡片上方的一句話結論
    fields=[
        Field("size_cm", float, label="直徑（公分）", min=0, max=30),
        Field("severity", str, label="嚴重程度", choices=["輕微", "中等", "嚴重"]),
    ],
    footer_notes=[],                                # 類別專屬頁尾，例如災情的 119 提醒
)
def hail(): ...   # 需要額外運算時才寫函式；沒有就留空
```

宣告裡的資訊，核心會自動用來：
- 加進分類器的選項，並產生該類別的 `claude -p` 提示詞與固定輸出格式
- 依 `fields` 驗證模型回傳（型別、範圍、選項）；不合格就拒絕，不寫入
- 清洗文字欄位與檔名，寫入 SQLite（類別欄位放 JSON，**不用改資料表**）
- 組出 embed 卡片：類別自己宣告圖示、結論、欄位；**頁尾（紀錄編號、信心、低信心免責）由核心統一加**
- 自動納入 `/history`、`/today`、`/help`

### 簡化不能犧牲正確性的規則
- **防護與驗證全部在核心，不在 handler / 類別裡。** 新類別沒辦法繞過四段防護，也沒辦法忘記做。
- 類別宣告載入時就檢查：缺欄位、重名、`headline` 引用不存在的欄位，一律啟動失敗，不要等到執行時才出錯。
- 每個類別必須附至少一組測試樣本（模型回傳 JSON → 預期卡片內容）；核心用同一套測試框架自動跑所有類別，沒有樣本就不能註冊。
- 新增類別前後，既有類別的測試都要通過，確認沒有互相影響。

範例：新增「`/wind 風速` 換算蒲福風級」指令，只需要：

```python
# handlers/wind.py
from core import command

@command("wind")
def wind(ctx, speed: float):
    level = beaufort(speed)
    return f"{speed} m/s 是蒲福 {level} 級"
```

### 第一版不做，但之後應該能用「新增一個檔案」補上
- 重判（對 agent 的回覆再回「重判」，重新分析並覆蓋舊結果）
- `/fix 欄位 新值`（修正紀錄）
- 定時主動推播（例如每天早上預報）
- 颱風、豪大雨警報提醒
- 英文與 `/setlang`
- 圖表 / 報表回傳、災情統計匯出

定時推播需要核心一次性加入排程機制，之後每個排程也是一個檔案。

## 不需要的
- 註冊、登入
- 網頁前端、GitHub Pages
- 長時間、大規模的雲端服務（這是開著才會動的本機程式）

## 技術上我知道的
- Python 3.12 + uv
- 圖片用 `claude -p` 在我這台電腦上處理
- Discord 用 Gateway（bot）模式，不需要 ngrok
- 外部天氣資料：台灣用中央氣象署開放資料（需免費申請授權碼），海外與備援用 Open-Meteo（不需金鑰）
- 紀錄存 SQLite
- 設定放在 `.env`（不 commit）：`DISCORD_TOKEN`、`CHANNEL_ID`、`CLAUDE_MODEL`、`DATA_DIR`、`DEFAULT_CITY`（選填，預設台北）、`CWA_API_KEY`（氣象署授權碼，選填；沒設就只用 Open-Meteo）

## 安全（四段防護）
1. `claude -p` 在只放這一張圖的暫存資料夾中執行
2. `claude -p` 可用的工具與權限受限
3. 使用者傳的文字與檔案一律當成資料，不混進給模型的指令（圖片附帶文字與 @bot 的問句也一樣）
4. 模型回傳的 JSON 要檢查格式與數值；檔名與儲存內容要清洗，回覆前也要跳脫 `@everyone` 之類的提及

## 做事的順序
1. 先做核心（Discord、排隊、儲存、`claude -p`、防護）與 handler / 類別註冊機制
2. 依序加入：圖片判讀 → @bot 文字查詢 → `/setcity` → `/history`、`/today`、`/delete`、`/help`
3. 自己測到正常，再補 `docs/architecture.md`、`docs/adding-a-feature.md`，並在 README 加上「功能」一節
